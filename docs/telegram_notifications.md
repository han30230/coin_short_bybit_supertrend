# Telegram 알림 설정

기본 OFF입니다. 매매 전략·금액·진입/청산 조건은 변경하지 않습니다.

## 1. 봇 생성과 채팅 ID 확인

1. Telegram의 공식 @BotFather에서 `/newbot`으로 봇을 만듭니다.
2. 받은 토큰을 PC/서버의 `.env`에만 저장합니다. 토큰을 GitHub나 채팅에 올리지 마세요.
3. 새 봇과 **본인 1:1 대화**를 열어 `/start`를 보냅니다.
4. 프로젝트 폴더에서 아래 명령을 실행해 본인 대화의 ID를 확인합니다.
   공유 봇에 여러 사람이 메시지를 보냈다면 ID가 여러 개일 수 있으니 임의로 선택하지 마세요.
   기존 webhook/poller가 업데이트를 소비한다면 별도의 알림 전용 봇을 사용하세요.

```bash
python -m coin_rising_short.notifications --chat-id
```

## 2. .env 설정

```dotenv
TELEGRAM_ENABLED=true
TELEGRAM_BOT_TOKEN=여기에_본인_봇_토큰
TELEGRAM_CHAT_ID=여기에_본인_채팅_ID
TELEGRAM_BOT_NAME=원하는_전략_이름
```

기본 봇 이름은 저장소마다 다르며, `BOT_ACCOUNT`가 있으면 계정명도 붙습니다.
세 저장소에서 같은 봇/채팅 ID를 사용해도 이름으로 구분할 수 있습니다.

## 3. 전송 확인과 실행

```bash
python -m coin_rising_short.notifications --test
```

이 명령은 Telegram 테스트 메시지만 보냅니다. 거래소 API 키를 요구하지 않고 매매 주문을 내지 않습니다.
성공 메시지와 실제 휴대폰 수신을 확인한 뒤 기존 방식으로 봇을 시작/재시작하세요.
`TELEGRAM_ENABLED=false`이면 기존 로그/CSV만 남기며 알림을 보내지 않습니다.

## 보내는 알림

- 봇 시작(초기화 중), 초기화 완료
- 실제 주문 상태를 재조회한 진입·청산 체결: 종목, 방향, 주문 ID, 체결가, 체결 수량
- 청산 가격 손익(수수료·펀딩 제외, 계좌 순손익 아님)
- 주문 접수 실패, 익절 주문 실패, 청산 실패, ERROR 이상 오류, ST 연속 손실로 종목 중단
- 체결을 확인하지 못하면 **체결 확인 필요**, 일부 체결만 확인되면 **부분 체결**로 구분

매매 기록에서 알림을 예약한 뒤 작업 스레드가 거래소 주문을 최대 3회 조회합니다.
알림용 조회는 주문을 내거나 매매 상태를 수정하지 않습니다.
일반 감시 로그와 주문 접수 성공은 체결 알림으로 보내지 않습니다.
오류 원문/스택은 키가 포함될 수 있어 보내지 않으며, 자세한 원인은 로컬 로그를 확인합니다.

## 한계

- Telegram 전송과 주문 확인은 매매 루프 밖의 제한된 큐에서 수행합니다.
  큐 포화·인터넷 장애·Telegram 실패 시 알림이 유실될 수 있지만 매매는 계속됩니다.
- 같은 주문 체결은 프로세스 내 최근 2,048건에 대해 중복 억제합니다.
  재시작을 넘는 정확히 한 번 전송은 보장하지 않습니다.
- 같은 출처/이벤트/종목의 오류는 5분에 한 번 보냅니다. ERROR 알림은 대기 중 일반 알림보다 우선합니다.
- 정상적인 예외 종료 때 최대 20초 동안 알림을 마무리합니다. 진행 중인 외부 요청이 길면 여전히 유실될 수 있습니다.
- 체결 미확인 알림 후의 최종 체결을 무기한 추적하지 않습니다. 거래소에서 확인하세요.
- 수동 청산/복구 등 실제 주문 ID가 없는 합성 기록은 체결 알림에서 제외합니다.
- 봇 강제 종료·PC 전원 차단·서버 장애 자체는 이 봇이 알려줄 수 없습니다.
  별도의 외부 생존 감시/정기 요약은 이번 변경에 포함하지 않습니다.
- 실제 토큰·채팅 ID가 없는 개발 환경에서는 실제 수신을 검증하지 않았습니다.

테스트: 거래소 키는 `test` 같은 가짜 값을 환경변수로 지정하고 `python -m pytest -q` 실행.
테스트 중 거래소나 Telegram으로 실제 주문/메시지를 보내지 않습니다.
