# 전체 수익 청산(Basket Profit Cycle)

이 기능은 봇이 관리하는 `st_mode` 롱·숏 포지션의 Bybit 미실현 손익을 부호 그대로 합산합니다. 합계가 목표 이상이면 새 진입을 막고, 봇 소유 미체결 주문을 취소한 뒤 관리 수량만 reduce-only 시장가로 청산합니다. 모든 청산을 거래소에서 확인한 후 상태를 초기화하고 다음 주기를 시작합니다.

## 설정

`.env`에서 설정합니다.

```dotenv
BASKET_TP_ENABLED=true
BASKET_TP_TARGET_USDT=100
BASKET_TP_STATE_FILE=basket_cycle.json
```

- 기본값은 활성화, 목표 `100 USDT`입니다.
- 목표 판정은 포지션별 손익을 상계한 값입니다. 예: `+130 - 30 = 100 USDT`.
- 진행 중에는 `BASKET_TP_ENABLED=false`로 바꿔도 안전을 위해 해당 청산 주기를 끝까지 복구합니다.

## 장애 및 재시작

- 취소·청산 의도를 먼저 `basket_cycle.json`에 저장하고 주문을 냅니다.
- 프로세스가 중단되면 같은 `orderLinkId`로 기존 주문을 확인해 중복 청산을 방지합니다.
- API 오류, 디스크 기록 오류, 수량 불일치 또는 소유권이 불명확한 포지션이 발견되면 성공으로 간주하지 않고 새 진입을 정지합니다.
- 같은 계정과 상태 파일로 봇 프로세스를 두 개 실행하지 마세요. 로컬 잠금은 같은 서버·같은 상태 파일에서만 중복 실행을 막습니다.
- `position_state.json`, `supertrend_watch.json`, `basket_cycle.json`을 청산 도중 삭제하지 마세요.

## 중요한 제한

- 트리거는 **미실현 손익 100 USDT** 기준입니다. 시장가 슬리피지, 수수료, 펀딩비 때문에 실제 최종 순이익은 100 USDT보다 작을 수 있습니다.
- 같은 종목·같은 방향으로 수동 주문이나 다른 봇을 함께 운용하면 거래소 수량만으로 소유권을 완벽히 분리할 수 없습니다. 수량이 늘었거나 외부 진입 주문이 겹치면 이 봇은 자동 청산 대신 정지합니다. 전용 계정 또는 서브계정을 권장합니다.
- 기존 상태가 `EXCHANGE_SYNC`처럼 거래소에서 자동 채택된 기록뿐이면 소유 수량으로 인정하지 않습니다. 먼저 포지션 소유권을 확인해야 합니다.
- 거래소 최소 주문 수량보다 작은 잔량이나 응답 불일치가 남으면 자동 초기화하지 않고 확인을 기다립니다.
- 완료 알림의 `price_pnl`은 이번 일괄 청산 체결가 기준 참고값이며 수수료와 펀딩비를 포함하지 않습니다.
